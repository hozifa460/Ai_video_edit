# إلى OpenCode — الدفعة التالية المقترحة: SR-06 فقط

اعتمد Codex الدفعة الأولى وجميع تصحيحاتها ضمن المصدر والحساب والرسم علىhost؛239 اختبارًا و14 حالة مستقلة ناجحة. التقرير `docs/reviews/CODEX_BATCH_01_UI_REVIEW_AR.md`. قياس الوسائط والأداء ما زال مفتوحًا، ولا تعِد تغيير الإصلاحات المتحققة.

اقرأ `AGENTS.md` و`PROJECT_MEMORY.md` من القرص، ثم بندSR-06 في `docs/reviews/SILENCE_REMOVAL_REVIEW_AR.md`. نطاق هذه الدفعة **SR-06 وحده**: التمريرة الثانية في `FfmpegSilenceDatasource.detectSilence` تستخدم `minSilenceDuration: 0.3` ثابتة بدل حد المستخدم.

المطلوب:

1. اجعل حد مدة الكشف المختار نافذًا في كل تمريرة؛ عند min2s لا تدخل سكتة مؤكدة بطول0.4s إلى الحذف بسبب التمريرة الثانية. حافظ على تمييزthreshold الخاص بالتمريرتين حيث لا يتعارض مع هذا العقد.
2. حافظ على union للتداخل/التلامس فقط، وعلىSpeech Guard والحماية الداخلية. `minSilenceDuration` حد اكتشاف السكتة الخام؛ لا تفسره كحد أدنى لطول الحذف النهائي بعدguards/breathing، ولا تعِد ملء فجوات محتوى.
3. أضف اختبارات تستدعي datasource الفعلي مع قناة محاكاة تتحقق من أوامر **كلتا التمريرتين** وتعيد نتائج مميزة حسب الأمر؛ لا تعتمد logs متطابقة لكل الحالات. اختبر min0.01/0.25/2/5، وفترات قبل الحد وعنده وبعده، مع حدود عائمة موثقة، وفجوة موجبة تبقىkept. اختبر pipeline بguards تقلل حذف سكتة خام مقبولة دون إسقاطها لمجرد أن الحذف المحمي صار أقصر منmin.
4. حافظ على بقية البنود المفتوحةSR-04/07/08/10/11/16/21/22/23. لا تغيّرVAD أو سياسةthreshold أوrender/stream selection أو ملكية الحالة ضمن هذه الدفعة.

شغّل `flutter analyze --no-pub` و`flutter test --no-pub` وكل ملفات قبولCodex المحفوظة. لا تعِد كتابة توقعات القبول أو سجلات المراجعة القديمة. احفظ نتائج جديدة وتقريرًا `docs/reviews/OPENCODE_SR06_RESULT_AR.md` يوضح السبب والملفات والاختبارات والقيود.

حدّث الذاكرة بعد التنفيذ بحالة **«منفذ — بانتظار مراجعة Codex»** لـSR-06 وحده. سيقرأ Codex الذاكرة قبل المراجعة ويحدثها بعدها. لا تعلن قياس كلام أوA/V أو تنفيذFFmpeg فعليًا اعتمادًا على محاكاةالقناة.
